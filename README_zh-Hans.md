# anti-fwd-spam

[English](README.md) | 简体中文

一个运行在 Cloudflare Workers + D1 上的 Telegram 群管理机器人：处理举报、拦截已登记来源 bot 的消息、维护账号和贴纸黑名单，并可启用决策模型判断语义不明确的垃圾消息。

## 适合谁

适用于需要在 Telegram 群中自动管理消息，并能维护以下基础设施的部署：

- 使用 Cloudflare Workers 和 D1 部署与保存数据。
- 给 bot 配置删除消息和限制成员所需的 Telegram 管理员权限。
- 启用模型分类时接受模型服务的隐私和费用边界。

完整功能建议使用**超级群**。普通群可以删除消息，但不能永久禁言。群主和管理员不会被自动禁言或封禁。确认后的封禁或删除可能影响历史消息，Telegram 无法恢复已删除内容。

## 它处理什么

| 场景 | 结果 |
| --- | --- |
| 授权举报人回复垃圾消息并提及 bot | 封禁被举报发送者，并清理符合条件的索引历史。 |
| 未授权成员提交有效回复举报 | 保存证据，不自动处罚。 |
| 消息来自已登记来源 bot | 删除当前消息；来源账号按独立规则处理。 |
| 新消息命中本地规则或已登记贴纸 | 删除当前消息；Telegram 支持时永久禁言发送者。 |
| 模型判断消息为垃圾消息 | 删除当前消息并禁言发送者，不处罚被引用作者。 |
| 新成员通过昵称或个人资料打广告 | 即使尚未发言，也永久封禁命中账号并删除入群通知。 |
| 消息被编辑或网络请求暂时失败 | 终止旧任务，只重试尚未完成的操作。 |

完整路由、保护条件和重试规则见[行为契约](docs/behavior.md)。

## 快速开始

1. 创建 Telegram bot，将它加入一个用于测试的超级群，并授予删除消息和限制成员的管理员权限。
2. 准备 Cloudflare Workers、D1、Git 和 `mise`。
3. 创建 D1、执行迁移、保存 Worker secrets、部署 Worker，并注册 `/webhook` 地址。
4. 在使用 `/bs` 或自动举报前，配置可信的举报身份。

完整的可复制部署步骤见[部署设置](docs/setup.md)。请先使用测试群，因为举报和封禁可能造成不可逆的删除。

## 日常使用

- **举报垃圾消息：** 用可信身份回复目标消息，并提及管理 bot。
- **登记来源：** 用可信身份发送 `/bs @source_bot`。来源名单也拦截 bot 直接发送的消息，包括 guest bot。
- **拉黑并举报 bot 来源：** 回复 bot 直接发送的消息并发送裸 `/bs`；对于内联消息，同样的命令会同时处理发送者和来源。
- **登记贴纸包：** 用 `/bs` 发送完整的 `https://t.me/addstickers/<set_name>` 链接。
- **解除误封或禁言：** 在受影响的超级群中，用可信身份发送 `/allow @username` 或 `/allow <账号 ID>`，移除对应黑名单并恢复访问权限。用户名解析限制及其他误报恢复见[运维手册](docs/operations.md)。

举报身份、管理员保护、来源归因、贴纸处理和误报恢复都由[行为契约](docs/behavior.md)定义。

成员有十条被 bot 观察到的合格消息自然超过历史索引保留期后，正文和个人资料的正则命中交给模型判断；未达到门槛时，正则先行直接处理，回复和引用同样适用。这是对低历史账号更严格的策略，示例或警告文字也可能被拦截；举报路由和管理员保护保留。计数及保留期边界见[行为契约](docs/behavior.md#member-maturity)。

## 可选的模型分类

配置受支持的服务商密钥后，可选的语义分类使用 GPT-6 Luna Decisions。密钥、路由和费用边界见[模型服务配置](docs/setup.md#optional-model-provider)；升级 Jev 部署前应先阅读[兼容性与迁移说明](docs/setup.md#compatibility-and-migration)。分类在本地规则、黑名单、贴纸检查和举报处理之后运行。bot 只发送受限的文本上下文和选定的个人资料，不下载或识别图片、视频、音频。

模型结合正文、图片说明、当前可见的名片名称和按钮判断发送者意图，不发送按钮回调数据。供货和招募不要求明确的出售动词或价格；警告、举报和分析不属于推广，即使图片说明或按钮中展示了广告样本。引用内容与查询到的资料保持来源隔离，本地规则标签不决定模型标签。未命中[本地规则](docs/behavior.md#local-filtering)的内容，只在符合条件的真人消息路径中进入模型；bot 只接受本地过滤。分数达到包含边界的阈值后处理当前消息，验收方式见[模型测试](docs/decision-checks.md)。

另有一条窄范围本地规则，沿用现有成员成熟度策略，匹配对可见色情资源特征的完整“射了”回复；引用内容或来源名称中的警告、举报、分析措辞不豁免该回复。成熟成员仍通过共享模型提示区分推广与警告、讨论。单独引用，或当前消息为询问、举报、较长分析文字，均不足以触发这条本地规则。

发送者直接要求审核器忽略规则或输出指定分数，也属于消息分类的拦截范围。讨论防护方法、引用或举报提示注入样本，本身不构成攻击。

只有有效模型分数才能触发处罚；无效答案和拒答不触发处罚。具体边界见[行为契约](docs/behavior.md#model-classification)。

运行真实模型测试前应阅读[模型测试](docs/decision-checks.md)。服务商配置应保存为部署 secrets，不要写入仓库文件。
